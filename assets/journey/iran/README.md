# The Iranian journey

Birth to adult life as a directed graph, compiled from the datasets under
`assets/text` into three binary files the game can load without parsing a CSV.

```
direction.bin   1,074 nodes + 20,385 edges     what can follow what
event.bin       20 authored events, 236 steps  the playable conversation
scenes.bin      17 scenes                      which backdrop each is staged on
scenes/         17 PNGs, 1920x1152             the backdrops themselves
```

Generated by `C:\temp\_script\journey_iran_build.py` from `journey_format.py`
and `journey_iran_events.py` — **edit those and re-run, never hand-edit the
`.bin`.** Backdrops come from `tools/art/build_journey_scenes.py`.

```powershell
python.exe C:\temp\_script\journey_iran_build.py
python.exe tools\art\build_journey_scenes.py
```

Both need **Windows** python: the build paths are `C:\` literals, and WSL
python3 treats the backslashes as one filename and silently writes a junk
directory instead of the game folder.

## The causal rule, which is the whole design

The datasets already contained the join and it had not been used yet. Every
goodlife row carries a `triggers` column — what a good thing exposes you to —
and the build maps each trigger onto the hurdle categories that may follow it.

> **A good event may only be followed by a hurdle one of its own triggers
> justifies.**

`goodlife:FOO-004`, a pomegranate, triggers nothing, so nothing can follow it.
That is what makes it a rest rather than a trap. `goodlife:TRV-143`, studying in
London, triggers `visa;border;airport;documents;credential`, so a visa refusal,
a secondary inspection, a document problem and a credential check are all legal
successors. **Visiting Isfahan cannot cost you a visa; going to Paris can.**

The mapping lives in `TRIGGER_TO_CATEGORY` in the build script — one table, 25
triggers, readable in a minute, and the only place the causality is decided.

| Edge kind | Meaning | Count |
|---|---|---|
| `consequence` | good → bad. The price of having done something. | 16,426 |
| `sequel` | good → good. The ordinary way a life continues. | 2,760 |
| `recovery` | bad → good. Not resolution — respite, always a pure good. | 740 |
| `cascade` | bad → bad. One hurdle dragging in the next. | 459 |

**228 of the 889 good events trigger nothing at all.** They are the floor of the
game: whichever difficulty was chosen at the menu, these stay reachable and
cannot be taken away. Most are `SEN`, `FOO`, `HUM`, `RST` and `NAT` — fruit in
season, laughing, sleep, weather.

## Nodes

| Source | Kind | Count |
|---|---|---|
| `goodlife` | good | 889 |
| `iran` | hurdle | 77 |
| `war` | hurdle | 69 |
| `general` | hurdle | 39 |

**Node ids are namespaced by dataset** — `goodlife:TRV-143`, `iran:VIS-001`.
This is not cosmetic. The four datasets collide on bare ids: `FIN-001`,
`PSY-001`, `DIS-001` and `EDU-001` each exist in more than one, and goodlife
`FAM-001` (a family memory) is a different thing entirely from iran `FAM-001`
(parents refused a visa). The first build keyed on bare ids, silently dropped
44 hurdles, and attached an authored event to the wrong node. The build now
asserts that node count equals rows read, so that cannot recur quietly.

## The format

One container, three kinds, little-endian, defined in `journey_format.py` and
read by `game/src/journey/journey_data.gd`. **Both halves must change together.**

```
 0  7  magic       "OCJRNY\0"
 7  1  kind        1 direction | 2 event | 3 scenes
 8  2  version     1
10  2  flags       reserved
12  4  count       records
16  4  records_at  offset of first record
20  4  strtab_at   offset of string table
24  4  strtab_len  interned string count
28  4  crc32       of everything from records_at onward
32     records     each u32 length-prefixed, so unknown records can be skipped
       strtab      u32 count, then count * (u16 length + utf-8 bytes)
```

Every string in a record is a `u32` index into the string table, and index 0 is
always `""` — so "absent" and "empty" are the same value and no reader needs a
null check. Records are length-prefixed, so **adding a trailing field bumps
`version` without breaking an older reader**; reordering or removing a field
does not have that property.

`direction.bin` carries nodes and edges in one stream, each record tagged
`REC_NODE` or `REC_EDGE`. A reader dispatches on the tag rather than assuming
order.

## event.bin: the datasets, turned round to face the player

The CSVs are third person, about somebody else, with citations — right for a
dataset, wrong for a game. The events are the same material in second person,
present tense, with somebody in the room saying something. Every event carries
`source_detail` pointing back at the row it dramatises, so the claim and the
scene cannot drift apart; the build **verifies the path basename matches the
node id** and refuses to compile if they disagree.

Conversation steps are deliberately the same set as `DialogueScript` in
`game/src/dialogue/dialogue_script.gd` — line, narration, choices, set, jump,
branch, command, end — so a compiled event maps onto **the dialogue runner the
game already has** instead of needing a second, parallel dialogue system.

Writing rules, enforced by review rather than by code:

- The player is *you*, and never speaks in their own name.
- Nobody explains the system to you. The clerk does not know he is a hurdle —
  he is bored, or kind, or following a rule he did not write.
- No number appears in dialogue unless a person in that room would say it. The
  statistics stay in the CSVs.
- If it is not in a dataset, it does not get a scene.

The 20 events run infancy → adult: being born, a name written down one letter
wrong, a pomegranate, a bicycle, the teacher who decided you were clever, the
konkur, the conscription card that turns out to be about the passport, Sharif,
the same degree becoming a flag, the first pay, Istanbul being easy, Turkey's
closed province, the London offer, the clearance refused with no reason, the
bank account closed by nobody, surrendering the only passport, medicine that is
not banned and cannot be paid for, parents refused, four letters on a boarding
pass, and the line at Pearson.

## scenes/

Composed by `tools/art/build_journey_scenes.py` from **Kenney's Roguelike Modern
City pack (CC0)**, already vendored under `art-source/kenney/`. Nothing is drawn
or synthesised: each scene is three tile bands — wall, detail, ground — plus a
few props, defined in `art-source/journey_scenes.json`. Re-dressing a scene is a
config edit, not an image edit. Licensing is recorded in
`art-source/LICENSES.md`, as the repo requires for any art source.

The horizon sits at the same height in every scene on purpose — it is what makes
cutting between them not feel like a jump.

## Known gaps, deliberately left for later tasks

- **Nothing plays this yet.** `JourneyData` loads and exposes the graph; it does
  not choose a path. That was the instruction — build the structure first.
- **`.bin` is not in `include_filter`.** `game/export_presets.cfg` ships
  `*.dlg,*.json` only, so a Steam or Android build would contain **no journey
  data at all** while the editor runs perfectly. That is the exact failure mode
  the repo's own `CLAUDE.md` warns about. It needs `*.bin` added to all three
  presets — and the files need to sit under `game/` — before anything can load
  them in a build.
- **Speakers are not registered.** The events use `mother`, `father`, `clerk`,
  `teacher`, `sergeant`, `advisor`, `friend`, `boss`, `pharmacist`, `teller`,
  `agent`, `officer`, `grandmother`, `email`. None are in
  `game/content/characters/characters.json`. They need adding before these
  conversations render with the right names and colours.
- **Officer Choi is a naming collision.** `characters.json` currently defines
  `choi` as *the player character, a detective*. The brief makes Officer Choi
  the final boss, a US immigration officer at Pearson. The existing
  police-procedural `.dlg` files are placeholders, but the conflict has to be
  resolved before the boss is written — and resolving it means touching content
  the test suite reads.
- **`SC-PEARSON` is dressed but unused.** The boss arena exists as a backdrop;
  the encounter is a later task.
- **Fan-out is capped** (6 consequences per trigger, 5 cascade, 8 sequel, 4
  recovery). Uncapped, one good event pointed at ninety hurdles and no designer
  could read the graph. Selection is deterministic, sorted by id, so a rebuild
  produces a byte-identical file.
